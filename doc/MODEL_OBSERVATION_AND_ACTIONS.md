# 模型输入、房间历史与动作空间

本文对应当前 `baseline_inference`、本地策略和人工轨迹 SFT 的共享状态投影。
完整拼接示例见 [POLICY_PROMPT_PREVIEW.md](POLICY_PROMPT_PREVIEW.md)。
模型看到的是公开游戏信息，不是原始 CommunicationMod 消息的所有字段。

## 1. 一次决策输入的组成

官方权重基线的 `canonical` 输入顺序为：

1. 玩家身份、存活目标、默认回合规则。
2. 只输出本次单个合法动作别名的格式要求。
3. 当前场景提示：战斗、地图、商店、事件、选牌、奖励等。
4. 当前公开状态：全局变量、牌组、遗物、药水、当前场景内容。
5. 当前房间历史：精简的动作语义、选牌用途和流程记录，不包含前后状态变化。
6. 本次合法动作别名表和最终输出提示。

状态和历史使用中文字段标签、分区、缩进和自然语言动作说明，不向该基线要求 JSON 输出。
底层仍是结构化 observation，便于审计、回放和使用相同内容生成 SFT。
`state_first`、`decision_first` 只改变区块顺序，不改变可见信息。

| --- | --- | --- |

| 遗物 | ID、名称、实时描述、公开计数器等 | 所有游戏内场景 |

| 地图 | 本幕公开的完整节点图及父子连接、当前位置、下一步节点、Boss 节点标志 | **仅 MAP**；非地图历史中也不复制地图全貌 |
| 战斗 | 回合；我方 HP、格挡、能量、姿态、Power；手牌；敌人的 HP、格挡、离场状态、Power、意图和伤害 | 正常战斗，以及战斗内 GRID/HAND_SELECT/CARD_REWARD |
| 当前界面内容 | 奖励、事件、商品、选牌目的/数量/确认状态等，见下表 | 对应场景 |
| 显式规则 | 遗物带来的禁止获得药水/金币、回合出牌上限、不可休息等已实现规则 | 规则存在时提供 |
| 流程记忆 | 当前房间历史；非普通战斗投影还保留已访问商店、已跳过奖励的运行记忆及选牌来源 | 用来辨别流程，不代表能看到隐藏结果 |

### 实体效果字段

实体信息来自游戏运行时对象；不加载静态知识库或经验文件。

- 卡牌核心字段：`id/name/type/cost/cost_for_turn/upgrades/is_playable/description`。
  源提供时还保留描述来源/完整性标记、`target`、伤害/格挡及基础值、
  `magic_number/hit_count/multi_damage`、颜色/稀有度和消耗、虚无、保留等标志。
  战斗手牌的 `final_single_hit_damage/final_block` 使用实时牌面缓存值，
  不在 Python 中重复叠加力量、虚弱等效果；单段值不代表多段总伤害，也不保证对每个目标都是最终扣血值。
- 药水：`id/name/description/target/can_use`，以及源提供的原始描述、来源、tooltips。
- 遗物：`id/name/description`，以及源提供的原始描述、来源、非负计数器。
- Power：`id/name/amount/type` 和源提供的运行时描述、来源、完整性标记。
- 伤害意图：单段实时伤害、段数、乘积得到的总意图伤害；未取得时为 `null`。
  持有符文圆顶时不提供敌人意图。

**当前模型投影中的抽牌堆、弃牌堆、消耗牌堆只有数量，没有逐张明细。**
Recorder 的原始日志可以保存明细，但不能据此声称模型已看到这些明细。
模型也不接收种子、RNG 状态、隐藏抽牌顺序或尚未翻开的牌面。

### 场景专属内容

| 场景 | `screen_state` / 附加上下文 |
| --- | --- |
| EVENT | 事件 ID、名称、正文、完整公开选项；翻牌事件附公开棋盘、尝试次数、配对情况 |
| SHOP_SCREEN | 全部已展示的卡牌、遗物、药水及价格，删牌是否可用、价格 |
| SHOP_ROOM | 当前可选入口；打开商人和离开房间是两步，不是购买动作 |
| COMBAT_REWARD | 公开奖励及类型、内容、金币量、奖励 ID/索引等；尚未打开的隐藏卡牌内容不猜测 |
| CARD_REWARD | 可选卡牌、所属奖励 ID；战斗内生成选牌附触发药水/卡牌来源与效果说明 |
| BOSS_REWARD | 可选 Boss 遗物及各自奖励标识 |
| GRID | 候选牌、移除/升级/变化用途、数量、已选牌、确认阶段、待确认牌、选择原因 |
| HAND_SELECT | 当前可选手牌、已选牌、数量限制、是否可选零张/任意数量、选择原因 |
| REST | 可用营火选项及是否已经使用；锻造仍拆为入口、选牌、确认、离开 |
| CHEST / 其他 | 游戏提供的公开标量字段与合法选择；未支持的复杂内容不会虚构补齐 |

## 3. 当前房间历史：`room_history`

这里的“完整”指**当前房间内已收到的动作及其必要操作含义**，不是每一步重新附上
整局所有房间的完整状态。离开过往房间后不再全文注入其历史；进入当前房间的那一步仍保留。
现有代码中房间边界以 `(act, floor)` 标识，界面切换本身不创建新房间：

- EVENT → GRID → 确认 → EVENT：同一房间。
- REST → 锻造选牌 → 确认 → REST：同一房间。
- SHOP_ROOM → SHOP_SCREEN → 星系仪奖励 → SHOP_ROOM：同一房间。
- 战斗 → 战后奖励 → 卡牌奖励：同一战斗房间。

保留规则：

- 所有房间统一最多显示最近 **30 条**记录，包括战斗奖励、事件和二级选牌；会告知总数、显示数和省略数。
- 超过 30 条时省略最早的动作行；当前事件初始说明仍单独提供，翻牌的已公开牌面仍保留在当前棋盘记忆中。
- 不再在底层只保留 16 条；完整房间历史不是从 UI 的六行摘要拼凑出来的。
- 新局清空历史。人工采集收到 `run_resumed` 时重置分段记忆，避免 Save & Load 前被回滚的分支当成当前已经发生的事。
- UI 的 `recent_actions` 使用模型同一份房间历史的最近六条，并调用同一文本渲染器；内容一致，只是条数更少。
- 30 步是显式历史窗口，不是字符串截断。不静默截断字符或丢弃超长样本；如果请求超出服务上下文，明确报错/暂停。
  人工 SFT 导出超出 `--max-length` 时失败。30 步也不保证一定满足模型的 token 容量。

历史对象包含：

```text
room: act / floor / room_type
total_steps / shown_steps / omitted_steps / limit（统一为 30）
event_opening: 当前事件最初的公开名称、正文和选项（如有）
steps: 按时间排序的操作记录
```

每条 `steps` 不只是一句“选择 A1”，而是：

- `step_id`、操作前后界面、前后回合、语义动作类型和规范 ID。
- 动作文本；不向模型提供执行来源（模型/人类/控制器自动动作等）。历史不使用易变的 `A1` 别名来代表实体。
- `details`：从动作前状态解析实际操作的卡牌/药水/奖励、敌人目标、选项文本、
  选牌用途/触发来源、奖励 ID、确认或返回时的已选卡牌等。实体仅保留稳定 ID、名称、升级次数和奖励标识；
  敌人目标仅保留索引、ID 和名称，不重复费用、效果描述、价格、伤害、格挡、生命等属性。
- 模型历史不包含 `observed_changes` 和 `event_changes`：不重复展开动作后的资源、
  Power、敌人状态、事件正文/选项等变化。当前资源、敌人和事件阶段由当前状态提供。
- 实际执行状态：排队后取消、跳过执行的尝试明确标注“未执行”，不当作已生效动作。

游戏内快速排队的出牌以已匹配的**执行入口**解析卡牌和上下文，不从下一步手牌倒推动作对象。
自动动作也进入历史，不要求模型再选一次；`environment_auto` 等执行来源仅保留在原始审计记录。
这与“由攻击药水/发现/星盘触发选牌”的**操作触发来源**不同，后者会保留，避免混淆选牌目的。

模型和 UI 使用相同的单行动作语义，例如：

```text
步骤135｜回合1：使用完美打击+ → 敌人0（史莱姆老大）
步骤40：选择事件选项：净化（事件→网格选牌）
步骤41：选择打击用于删除
步骤42：返回（已选牌：打击；用途：删除）
步骤31：翻开位置0（当前位置已公开：痛击）
```

营火锻造、商店删牌仍按入口、选牌、确认/返回分别记录，不合并成已完成动作；
奖励界面区分打开卡牌奖励与领取奖励，并保留奖励 ID。未执行的排队尝试会明确标注。

### 翻牌小游戏

当前棋盘持久保存每个位置是否曾揭示、当前是否翻开、是否已配对、已公开的卡牌。
**牌重新盖回去后，曾公开的牌面仍可见。** 未揭示的牌面一律保持未知。

每次翻牌历史保存稳定位置，并可关联该位置当前已公开的牌面；
尝试次数、配对情况等只在当前棋盘状态提供，不在历史中重复记录其前后变化。
如果动作后快照早于翻牌动画完成，可以从**当前公开棋盘**补上“该位置当前已公开的牌面”，
但不把它谎称为当时快照已确认的最终结果。选择列表索引不等于棋盘位置：优先使用
Recorder 的 `board_position`；在线只在明确的 `cardN` 标签中解析位置，不猜测缺失值。

### 动作后状态的界限

原始轨迹的前后状态仍保留用于复盘和审计；后状态不保证动画全部结束，
也不是严格的单动作因果标签。模型房间历史不包含这类前后状态变化。
当前状态才是下一步决策依据；训练标签仍由动作前状态和实际动作组成，
不使用当前样本动作执行后的状态预测当前样本答案。
后状态未及时提供的中间公开细节无法凭空恢复；因此不能承诺记录了游戏的每一动画帧。

## 4. 动作空间与输出

模型不直接输出鼠标位置、键盘事件或任意命令。controller 将当前 CommunicationMod
允许的操作展开为细粒度语义动作；在基线 API/SFT 中按当前列表顺序赋别名：

```text
【合法动作】
- A1：出牌 打击 -> 敌人 0
- A2：出牌 防御
- A3：结束回合
请输出唯一的动作 ID：
```

模型答案例如 `A2`，由本次别名表映射到 `PLAY:card=2`，再编译为游戏命令。
`A2` **不是**固定的“防御”或固定卡牌：下一状态会重新编号。
输出不允许额外解释/JSON。Candidate Assist 的排序接口和远程教师有各自输出包装，
不要将其包装误当成基线的单动作标签。

| 语义操作 | 规范 ID / 命令示例 | 粒度 |
| --- | --- | --- |
| 出牌 | `PLAY:card=1:target=0` / `PLAY 1 0` | 一张牌和一个敌人目标；无目标牌只一个动作 |
| 结束回合 | `END_TURN` / `END` | 一步 |
| 使用/丢弃药水 | `POTION_USE:slot=0:target=1`、`POTION_DISCARD:slot=0` | 一瓶及需要的目标 |
| 选择选项/卡牌/商品/奖励/节点 | `CHOOSE:index=0` / `CHOOSE 0` | 一次当前界面的选择，不是组合宏动作 |
| 确认或继续 | `CONFIRM` 或 `PROCEED` | 与选牌、进入地图分开记录 |
| 返回/取消/跳过/离开 | `RETURN`、`CANCEL`、`SKIP`、`LEAVE` | 仅当前协议提供且合法时出现 |
| 关闭设置覆盖层 | `KEY:CANCEL` / `KEY Cancel` | 不同时暴露覆盖层下的战斗动作 |

出牌手牌位置是 **1-based**；敌人目标、药水栏位、CHOOSE 索引是 **0-based**。
手牌索引、选择索引、棋盘位置、动作别名是不同概念。

地图不提供药水使用/丢弃动作；地图节点以实际合法选项为准（包括飞鞋规则）。
非战斗场景可丢弃药水，主动使用只开放鲜血药水/果汁；战斗药水按可用性和目标展开。
多选场景只提供尚可选择的实例与合法确认/返回动作。人类原始操作还可能包含取消选中，
采集保留这些细粒度尝试，但最终 SFT 可用性由现有标记决定。

## 5. 实现路径与更新后的数据

- `sts_agent/runtime/controller.py`：规范化、历史入口、状态投影和合法动作。
- `sts_agent/policy/history.py`：原始审计动作解析、精简历史投影、UI/模型共享文本渲染、房间划分和统一 30 步窗口；上限由 `ROOM_HISTORY_LIMIT` 定义。
- `sts_agent/policy/local_qwen.py`：中文渲染、场景提示、单动作 prompt。
- `sts_agent/policy/api.py`：本次动作别名、远程请求、状态复核和严格解析。
- `sts_agent/recording/trajectory_assembler.py`：人工采集与回放使用相同历史构造。
- `sts_agent/learning/export_human_sft.py`：回放原始 Recorder 数据、生成相同输入的 SFT。
- `sts_agent/commands/preview_policy_prompt.py`：生成文档中的完整示例。

旧的已导出 SFT 文件不会自动变成新历史格式。需要用原始 Recorder 数据重新导出；
原始状态未记录的牌面/说明不能恢复。历史逻辑在本机 controller/bridge 中执行，
远端常驻基线服务只负责推理，不需要为了本次 prompt 改动重新下载模型。
