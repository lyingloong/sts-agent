# 本地策略模型自然语言 Prompt

本地 Qwen 策略模型使用 `sts_agent.policy.local_qwen` 中的统一模板。推理、SFT 数据构造和 online RL 的动作概率评分都调用同一个 `build_scoring_prompt`；候选动作排序调用同一状态渲染器和 `build_prompt`。因此不要在训练模块里另行拼接 prompt。两种模式共用相同的开头和状态组织，只有输出协议不同。

## 固定规则

默认继续使用 `plain_text / canonical`，Markdown 方案仍为待开发。
开头只说明正在游玩《杀戮尖塔》，不额外固定第三幕通关或心脏等终局目标。

通用句只保留“结合当前状态与房间历史，权衡生存、牌组成长和资源收益。”；具体代价、效果和限制由当前场景信息表达。
动作仍从当前合法动作表中选择，只输出单个原样动作别名。候选排序模式保留自己的JSON协议。

所有场景简要说明默认3能量、抽5张牌和战后回血规则。战斗及战斗内选牌额外说明：
未保留能量/手牌的回合结束处理、格挡通常在自己的下一回合开始时清除，以及X费的含义。
当前游戏效果优先于默认规则。手牌伤害/格挡按当前牌面理解，已反映在牌面上的状态修正不重复计算；
实际扣血仍需结合目标状态、格挡和攻击段数判断，不承诺单一牌面值就是每个目标的最终扣血。
钥匙区说明：集齐红、绿、蓝三把钥匙，才能在击败第三幕Boss后进入第四幕。

## 场景提示

场景提示只提供决策重点，不替代游戏规则，也不把策略写成硬约束：

- 地图：读取完整公开地图和当前可达节点，根据生命、牌组、资源和首领风险比较路线；不使用战斗提示。
- 战斗：结合手牌、资源、敌人意图和状态安排攻防；有有效出牌或药水收益时不要无故结束回合。
- 卡牌奖励：比较全部可见卡牌；前期关注能解决当前战斗的过渡牌和牌组协同。
- 战斗奖励：通常领取尚未领取的可用资源，同时权衡互斥奖励与药水栏位。
- 事件：结合当前正文、选项和房间历史判断事件阶段，权衡代价与收益。
- 商店房间（SHOP_ROOM）：处理打开商人或离开房间，不猜测尚未展示的商品。
- 商人界面（SHOP_SCREEN，SHOP 别名）：比较价格、牌组缺口、遗物、药水和移除牌价值，不重复提醒退出商人、离开房间等控制流程。
- 营火、Boss 奖励：根据当前生命、牌组缺口、路线和首领风险比较选项。
- 战斗内生成选牌：药水或出牌产生的 CARD_REWARD 按战斗即时效果比较，不套用永久牌组奖励的策略；来源缺失时不猜效果。
- 多选/选牌：区分升级、移除、变化、一般选择和选后确认；遵守触发来源、数量和已选项目，合法取消/少选不被提示词禁止。
- 翻牌事件：读取公开棋盘和曾揭示的牌面记忆，未揭示的牌面保持未知。
- 宝箱、过渡和终局：各自提供流程提示；未知界面使用通用提示，只依据合法动作和公开状态。

所有入口通过 `sts_agent.policy.scenes` 统一分类，本地短提示与远程教师详细提示分别维护。
`CARD_REWARD` 的战斗/遗物语义、`GRID` 的目的/确认阶段属于提示词场景分类，不改写原始状态或动作 ID。

## 状态组织

状态由控制器先经过 `route_policy_observation`，再由 `render_observation` 转成中文自然语言：

- 全局：界面、房间阶段、楼层、幕、角色、进阶、生命、金币、本幕首领名称。
- 资源：当前牌组（按相同公开卡牌属性汇总计数）、遗物、药水及状态源实际提供的运行时描述。
- 战斗：我方能量/状态、当前姿态（ID、名称、运行时描述）、手牌运行时描述和游戏提供的伤害/格挡数值、敌人生命/意图/状态及意图伤害，以及三种牌堆的数量和公开卡牌组成。
- 当前界面：事件、奖励、商店、营火、选牌等界面的可见内容，以及游戏状态中实际提供的实体说明。
- 上下文：最近动作、事件历史、本局记忆、遗物造成的决策限制和选牌上下文。
- 地图：只有 `screen_type=MAP` 时显示完整节点图；战斗、事件、奖励、商店等场景不会带地图全貌。

手牌、敌人、库存药水和选择项带明确位置；动作别名保留安全位置元数据，不能用A别名序号代替手牌或选择位置。
手牌位置从1开始，敌人、药水栏位和选择位置从0开始；商品数组顺序不被猜作CHOOSE顺序。
升级GRID可展示上游的 `upgrade_preview`；确认页使用完整待确认卡牌。未取得安全预览时明确显示未知。

`text_observation` 只清理展示副本：完整实时描述替代重复的伤害、格挡、基础值、效果参数和段数字段，
去掉重复费用、无内容的多目标数组、固定来源和已确认false的可省略属性。费用、不同的本回合费用和描述未体现的实例属性仍保留。
描述明确不完整、完整性未知、含未解析变量或raw另有独有效果时，保留必要的原说明与数值兜底；敌人意图、我方格挡和Power层数不属于卡牌字段去重。
多目标伤害若确有差异且能可靠对应敌人序号，则显示“按目标区分的单段伤害”；不从未知或不匹配的数组猜测对应。
奖励编号仅在内部数据保留，不进入正文或历史动作文本；互斥关系转换成具名说明，例如蓝钥匙与某件遗物二选一。
空药水槽只显示槽数；未知、说明不完整、真实属性差异和额外tooltip继续保留。
CommunicationMod 的药水数组包含空栏位，容量由源数组长度取得，不默认假设为3；缺失数据才显示未知，真实空数组表示0栏位。
“可打出”只在当前战斗手牌中展示；牌组、奖励和升级预览不是可直接出牌的对象，不展示其无意义的可打出缓存。
原始消息与完整规范化记录不因此删除字段。历史直接展示动作行，不再重复“以下为过去操作”或固定的30步窗口说明；只有确有省略时提示省略了多少步。
内部仍保留最近30步的窗口，取消或未执行的尝试在对应动作行标注，不另加通用解释。
`action_phase` 是流程就绪/调度字段，只在原始数据和内部逻辑保留，不放入动作模型提示词。
原始 `choices` 列表仍供动作映射使用，但不再单独展示为【当前选择】，避免与【合法动作】重复；场景内选项的效果、代价等说明仍保留。
事件开场历史同样只保留详细选项已覆盖之外的choice；若上游只有choice或详细选项不完整，未覆盖信息显示为“当时可选项”，不冒充当前合法动作。

在实际战斗阶段，GRID、HAND_SELECT、CARD_REWARD 仍保留战斗状态（能量、手牌、意图、Powers 等），
不能仅因选牌弹层打开就删除这些决策信息。非战斗阶段和地图不注入残留战斗快照。
抽牌堆、弃牌堆和消耗牌堆按公开属性归并并确定性排序，只展示卡牌组成，不暴露隐藏抽牌顺序。
非手牌不把临时目标伤害/格挡缓存当作下次打出的数值；完整说明替代重复基础值，说明不完整时保留必要兜底。源未提供或部分牌缺失时保持未知，不编造实体。
姿态保存在 `combat.player.stance`，直接使用源的 `id/name/description`；源未提供时为 null，
不默认推断为正常姿态。Recorder 原始记录已有此字段时，重新导出 SFT 即可补入模型输入。
翻牌状态使用已公开的 `match_game` 棋盘记忆，未揭示牌面在下游投影中再次置为 null。

未知值显示为“未知”，已知字段使用中文标签；未知的新增公开字段仍会以原字段名保留。描述只来自当前游戏状态；本地静态实体知识库和 Boss 攻略已移除，不按 ID/名称回填。

## 输出协议

候选排序模式输出：

```json
{"ranked_action_ids":["A1","A2"]}
```

概率评分和 SFT 模式输出：只输出一个合法动作 ID，例如 `A2`，后跟换行。禁止输出解释、Markdown、命令或不在合法动作列表中的 ID。

输入不做字符或 token 截断。人类 SFT 导出指定 tokenizer 后默认上限为 8192 token，任一完整样本超限会报错并终止整个导出，不因超长悄悄丢弃步骤。训练器仍会检查自己的上下文上限，训练配置应与完整数据长度匹配。状态渲染地图只在 MAP 场景呈现完整图，避免其他决策反复携带地图。

修改场景模板或状态路由后，应从 Recorder 提取包重新导出 SFT；训练编码器会拒绝与当前渲染器不一致的旧 prompt，不能混用旧预览和新推理模板。
