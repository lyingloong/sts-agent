# 本地策略模型自然语言 Prompt

本地 Qwen 策略模型使用 `sts_agent.policy.local_qwen` 中的统一模板。推理、SFT 数据构造和 online RL 的动作概率评分都调用同一个 `build_scoring_prompt`；候选动作排序调用同一状态渲染器和 `build_prompt`。因此不要在训练模块里另行拼接 prompt。两种模式共用相同的开头和状态组织，只有输出协议不同。

## 固定规则

Prompt 的开头是“你正在游玩《杀戮尖塔》，负责完成整局游戏”，而不是教师模型或只负责战斗的子模型。每次只允许从通信控制器给出的合法动作中选择，动作 ID 是程序接口令牌，必须原样输出。

目标按以下优先级表达：

1. 避免死亡和不必要的掉血。
2. 处理当前最紧迫的战斗、选择或流程目标。
3. 在不牺牲当前生存率的前提下，改善牌组、遗物、药水、金币和路线。
4. 结合已经公开的本幕首领和后续路线做长期决策。

Prompt 中会提醒基础规则：没有额外效果时，每回合开始获得 3 点能量并抽 5 张牌，回合结束失去剩余能量并弃掉手牌；普通战斗结束不会自动回血，击败 Boss 后通常回复较多生命。当前状态中的实际数值和牌/遗物效果优先于这些默认规则。

## 场景提示

场景提示只提供决策重点，不替代游戏规则，也不把策略写成硬约束：

- 地图：场景提示与战斗共用；状态正文仍只在地图界面显示完整地图，模型根据可见路线和合法节点动作选路。
- 战斗：先看生命、能量、手牌、敌人意图和计算后的伤害/格挡；有有效动作时不要无故结束回合。
- 卡牌奖励：比较全部可见卡牌；前期关注能解决当前战斗的过渡牌和牌组协同。
- 战斗奖励：先处理仍未领取的金币、药水和遗物，再决定卡牌奖励或跳过。
- 事件：读取事件说明和事件历史，确认当前处于哪个阶段，避免重复上一阶段选项。
- 商店：确认商人和商品后再比较价格、牌组缺口、遗物、药水和移除牌价值；离开后不要重复进入同一商店。
- 营火、Boss 奖励：根据当前生命、牌组缺口、路线和首领风险比较选项。
- 多选/选牌：读取当前触发来源和选择要求，已选项目不能重复选择。

## 状态组织

状态由控制器先经过 `route_policy_observation`，再由 `render_observation` 转成中文自然语言：

- 全局：界面、房间阶段、楼层、幕、角色、进阶、生命、金币、本幕首领名称。
- 资源：当前牌组（按卡牌和升级次数计数）、遗物、药水及状态源实际提供的运行时描述。
- 战斗：我方能量/状态、手牌运行时描述和游戏提供的伤害/格挡缓存、敌人生命/意图/状态及意图伤害、牌堆数量。
- 当前界面：事件、奖励、商店、营火、选牌等界面的可见内容，以及游戏状态中实际提供的实体说明。
- 上下文：最近动作、事件历史、本局记忆、遗物造成的决策限制和选牌上下文。
- 地图：只有 `screen_type=MAP` 时显示完整节点图；战斗、事件、奖励、商店等场景不会带地图全貌。

未知值显示为“未知”，已知字段使用中文标签；未知的新增公开字段仍会以原字段名保留。描述只来自当前游戏状态；本地静态实体知识库和 Boss 攻略已移除，不按 ID/名称回填。

## 输出协议

候选排序模式输出：

```json
{"ranked_action_ids":["A1","A2"]}
```

概率评分和 SFT 模式输出：只输出一个合法动作 ID，例如 `A2`，后跟换行。禁止输出解释、Markdown、命令或不在合法动作列表中的 ID。

训练输入不做字符截断；token 上限由数据导出/训练器按完整样本过滤并报告。状态渲染地图只在 MAP 场景呈现完整图，避免其他决策反复携带地图。
